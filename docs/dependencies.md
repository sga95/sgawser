# Dependencies

Everything sgawser relies on that the project did not write: code, data, services, hosting, tools, and the apps the guides ask people to install. Nothing is built yet, so the list has two parts: what is in use today, and what the design plans to use.

Facts were read on 2026-11-10, most of them on each project's own pages. Some come from Wikipedia or another outside page, and a few are general knowledge not re-checked that day; the rows say so. A completeness pass on the same day added the rows it found missing. A missing row is still possible: open an issue if you find one.

## The rules

**Order of preference for every need.**

1. Drop the need.
2. Use what the platform and the engine already contain.
3. Write it in the project, in plain code, when it is small and is not a security standard.
4. Take a third-party part only as a written exception in this list.

**Never home made.** The engine, cryptography and hashing, signature formats, TLS and certificate checks, the update path and the repository format, the parsing of addresses. For these the project uses the platform's or the engine's implementation, or a named existing standard.

**What a third-party part should be.** Open source; run by a community or a non-profit, not by a company that sells it or makes money from it; transparent about who runs it and how it is paid for. The author also applies criteria of his own that are not written here for now.

Many rows below do not meet these rules. Only one exception has been decided by the author so far: the engine. Every other row marked "exception proposed" is a proposal waiting for his decision. "Undecided" marks a choice with more than one option open.

## Written in the project (planned)

The network gate and the local network log. The simple and expert modes and the routine that checks the protections. The address check rules and its small lists (brands, link shorteners, pressure words). The help texts, in English and Italian; another language ships only when a named person has read every warning in it. Theme colours. The scripts that count lines, check patches, run the tests and draft each release record. A local server for most test pages. The test that reads a capture and counts connections. The short list of websites the tests are run against, with the date each was tried.

## Withdrawn or left out

| What | Why |
|---|---|
| MetaGer as default search | It needs a paid key since September 2024 |
| Google Play, Google Safe Browsing, Google's DRM module download | Google services; the browser is designed to contact none of them. Limits: without Safe Browsing there is no warning about malware pages and almost none about new fake login pages; without the DRM module protected video services do not play; on certified phones Google's own install check still runs |
| Other phishing and malware lists | Each fails a rule or its own terms: Phishing Army names a company sponsor; the CERT-AGID feed is only for public administrations; URLhaus is run together with Spamhaus and shared with Google Safe Browsing; PhishTank belongs to Cisco (per Wikipedia) |
| Digitalcourage resolver | Left out as a secure DNS choice: it offers DNS over TLS only (per a third-party directory, not its own page) |
| An update check inside the browser | Proposed to be left out, not decided yet: updates would come through the repository client, and an own update protocol would be home-made security |
| JavaScript tooling (Node.js, npm, Wrangler) | Not used in this repository. The ignore rules that name its folders only guard against committing them by mistake |
| Any library added by sgawser's own code | The own layer adds none |
